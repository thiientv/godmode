# Discovery questions

Use only the questions that can change the design.

## Outcome

- Who has the problem and what do they do today?
- What must become possible, faster, safer, or clearer?
- What is the smallest observable success?

## Boundaries

- Which surfaces are in scope: code, data, API, UI, deployment, or docs?
- Which existing contracts must remain compatible?
- What is explicitly out of scope for this change?

## Risk

- What can lose data, money, access, privacy, or user trust?
- Which dependency, migration, or environment assumption is least certain?
- What is the rollback or safe-disable path?

## Evidence

- Which user path, test, command, screenshot, response, or metric can falsify
  the success claim?
- Which check is impossible in the current environment and why?
